NATS and JetStream for failure handling

The mechanics behind failed messages on NATS, built for making design decisions in a microservice system. NATS has no built-in dead-letter queue. Failure handling is assembled from acks, delivery limits and advisories, so the course builds those up in order: core NATS first, then streams, consumers and acks, then how delivery gives up and the DLQ pattern. Code examples use TypeScript (nats.js v3). Nine lessons, an interleaved quiz, a glossary, and a printable cheat sheet.

Arc 1 · Core NATS

What NATS does with no persistence at all, and why that is the baseline every later decision is measured against.

L1 Subjects and at-most-once deliverySubjects, tokens and wildcards. Delivery goes to whoever is listening right now, and nothing is kept, so nothing can be retried. → L2 Queue groups and request-replySpreading work across replicas and asking for one answer, both with nothing stored, and why no-responders and a timeout mean different things to a caller. →

Arc 2 · JetStream

Storage, the cursor that reads it, and the acknowledgement loop that turns at-most-once into retry.

L3 Streams and retentionA stream stores and numbers every message on its subjects. Limits, Interest and WorkQueue decide when a message is removed, which later decides whether a failed one can still be found. → L4 Consumers: a cursor on the streamA consumer is a server-side position on a stream. One consumer per service fans out; many workers on one consumer share the work. → L5 Acks and redeliveryAck, nak, term and in-progress, the AckWait timeout that covers crashes, and MaxAckPending as the cap on work in flight. →

Arc 3 · When delivery fails

How delivery gives up, the signal it sends, and how a dead-letter queue is assembled from those parts. Closes on one service designed end to end.

L6 Giving up: MaxDeliver and BackOffMaxDeliver defaults to unlimited. BackOff spaces out timeout redeliveries only. A term counts as an ack and hitting MaxDeliver does not, which decides whether the original survives. → L7 AdvisoriesThe signal JetStream sends when it gives up on a message: published once, never stored, and skipped when nothing listens, so it has to be captured in a stream. → L8 The DLQ pattern on NATSCapture the give-up advisories, fetch each failed message by stream sequence, and copy it into a DLQ stream while it still exists. Plus the places the pattern leaks. → L9 Designing failure handling for one serviceAn order-fulfilment worker designed end to end: layer and retention, consumer config, handler responses per error class, the DLQ, replay and monitoring. →
