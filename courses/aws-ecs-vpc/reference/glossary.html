VPC and ECS at whiteboard depth · Reference

Glossary

Canonical vocabulary for this course. Every lesson uses these terms exactly as defined here, and the definitions follow the AWS documentation rather than common usage where the two differ. The last table lists the terms the course names on purpose without teaching them, so the gaps are visible.

The network

TermDefinition
VPCA virtual network dedicated to one AWS account, logically isolated from other virtual networks in the AWS Cloud. Defined by an IP address range, scoped to one Region, spanning that Region's Availability Zones. Nothing runs it; it is a definition that resources plug into. (Lesson 1)
RegionA geographic AWS location containing several Availability Zones. A VPC belongs to exactly one, and so does an ECS cluster. (Lesson 1)
Availability ZoneA distinct location within a Region, engineered to fail independently of the others. The unit of failure, and therefore the unit of redundancy. (Lesson 2)
CIDR blockAn address range written as a prefix and a length, such as 10.0.0.0/16. A VPC has one; each subnet takes a smaller, non-overlapping block out of it. (Lessons 1, 2)
SubnetA range of IP addresses in a VPC. It must reside in a single Availability Zone, which is why choosing a subnet is choosing a failure domain. Resources draw their private address from the subnet they are placed in. (Lesson 2)
Default VPCThe VPC AWS provides in each Region for accounts created after 4 December 2013. It has a default subnet in every zone, an attached internet gateway, a main route table route to that gateway, and public DNS hostnames enabled. It is a set of pre-made decisions, not an absence of them. (Lesson 1)
Route tableA set of rules, called routes, determining where traffic from a subnet or gateway is directed. Each subnet uses exactly one: the one explicitly associated with it, or the main route table. (Lesson 3)
Main route tableThe route table created with the VPC. It controls routing for every subnet not explicitly associated with another table. (Lesson 3)
Route: destination and targetA route pairs a destination, the range of addresses traffic is headed for, with a target, the gateway, network interface, or connection to send it through. (Lesson 3)
Local routeThe default route for communication within the VPC, present in every route table. It is why any resource can route to any other in the same VPC without configuration. Routing is not permission. (Lesson 3)
Public subnetA subnet whose route table sends 0.0.0.0/0 to an internet gateway. Not a flag, not an attribute, not about which addresses the resources hold. (Lesson 3)
Private subnetA subnet with no route to an internet gateway. Its resources reach the internet, if at all, through some other target such as a NAT gateway. (Lessons 3, 4)
Internet gatewayA gateway attached to a VPC that lets resources connect to the internet through the Amazon EC2 network edge. The only door through which something outside can initiate a connection inward. (Lessons 3, 4)
NAT gatewayAn address translation service letting resources in a private subnet connect out while external services cannot initiate connections to them. A public NAT gateway lives in a public subnet with an Elastic IP address and routes onward to the internet gateway. Connections must always be initiated from within the VPC. (Lesson 4)
Elastic IP addressA static public IPv4 address allocated to your account and associated with a resource such as a NAT gateway or an instance. (Lessons 1, 4)
VPC endpointA way to reach an AWS service or a service in another VPC using private addresses, with traffic staying on the AWS network. An interface endpoint places an endpoint network interface in your subnet; a gateway endpoint serves Amazon S3 and DynamoDB through the route table and does not use AWS PrivateLink. (Lesson 4)
AWS PrivateLinkThe service behind interface endpoints: clients in your VPC connect to services and resources in other VPCs using private IP addresses, as if those services were hosted in your own VPC. (Lesson 4)
Elastic network interface (ENI)A virtual network card in a subnet, carrying a private address and the security groups attached to it. In awsvpc mode each ECS task gets its own, created with the task and deleted when it stops. (Lesson 8)
Security groupA stateful allow-list attached to a resource's network interface. Allow rules only, all rules evaluated, return traffic permitted automatically. Rules may reference other security groups instead of addresses. (Lesson 5)
Network ACLA stateless filter attached to a subnet. Allow and deny rules, evaluated in ascending order until a match, with return traffic needing its own explicit rule. AWS positions it as coarse guard rails and defence in depth, not the primary control. (Lesson 5)
Group-references-groupWriting a security group rule whose source is another security group, so the policy names a role rather than an address. What keeps rules correct while tasks are replaced and scaled. (Lessons 5, 8, 9)

The compute

TermDefinition
Amazon ECSA fully managed container orchestration service. Split by the docs into three layers: capacity, the infrastructure where containers run; controller, which deploys and manages applications; and provisioning, the interfaces you use. (Lesson 6)
ClusterA logical grouping of tasks or services that provides the infrastructure capacity for containerised applications. Region specific. Its components include the VPC and subnets where the work runs. Not a set of machines. (Lesson 6)
Task definitionA blueprint for an application: a JSON document describing one or more containers and their parameters, including images, CPU and memory, network mode, logging, and the IAM role tasks use. Registered as numbered revisions. Nothing runs when you write one. (Lesson 6)
TaskOne running instantiation of a task definition within a cluster. All containers in the definition are placed together and live and die together. (Lesson 6)
ServiceA controller that runs and maintains a specified number of instances of a task definition. If a task fails or stops, the service scheduler launches a replacement. Optionally sits behind a load balancer. (Lesson 6)
Service schedulerThe part of ECS that compares desired count with actual and acts on the difference, including replacing tasks that fail a container health check or a load balancer target group health check. (Lessons 6, 9)
Desired countThe number of tasks a service is asked to keep running. Scaling changes this number; the reconciliation behaviour around it never changes. (Lesson 6)
Service auto scalingAutomatic adjustment of a service's desired number of tasks, implemented through Application Auto Scaling. (Lesson 6)
CapacityThe ECS layer that supplies the infrastructure tasks run on: Fargate, EC2 instances, ECS Managed Instances, or external instances. Independent of the controller layer above it. (Lesson 7)
AWS FargateServerless capacity: run containers without provisioning, configuring, or scaling clusters of virtual machines. Each Fargate task has its own isolation boundary and shares no kernel, CPU, memory, or network interface with another task. (Lesson 7)
Platform versionA Fargate runtime environment, combining kernel and container runtime versions. New tasks always start on the latest revision, which is how patching reaches workloads with no host to patch. (Lesson 7)
Fargate SpotFargate capacity running on spare compute at a discount, interrupted with a two-minute warning when AWS needs it back. Suits interruption-tolerant work. (Lesson 7)
ECS Managed InstancesEC2 instance types with infrastructure management offloaded to AWS, which handles provisioning, patching, scaling, and maintenance. Currently the docs' recommended choice for most new workloads. (Lesson 7)
ECS AnywhereRegistration of an external instance, such as an on-premises server or virtual machine, to an ECS cluster. (Lesson 7)
Launch typeTelling ECS to launch tasks directly on Fargate or on the EC2 instances registered to the cluster. The simpler of the two ways to choose capacity. (Lesson 7)
Capacity provider strategyDistributing tasks across one or more capacity providers, with weights. How a single service splits between, say, Fargate and Fargate Spot. (Lesson 7)
awsvpc network modeThe network mode giving tasks the same networking properties as EC2 instances: one elastic network interface per task, a private IPv4 address, and the security groups you specify. Required for Fargate. (Lesson 8)
Network configurationThe subnets and security groups given when running a task or creating a service. Placement follows the subnets, so it is also the availability decision. Currently limited to 16 subnets and 5 security groups. (Lesson 8)

Where they meet

TermDefinition
Application Load BalancerA layer 7 load balancer serving as the single point of contact for clients and distributing traffic across targets in multiple Availability Zones. (Lesson 9)
ListenerThe part of a load balancer that checks for connection requests using a configured protocol and port. (Lesson 9)
RuleA listener's routing decision, made of a priority, one or more conditions, and one or more actions. Layer 7 conditions can match paths and hostnames. (Lesson 9)
Target groupThe list of registered backends a rule forwards to, with health checks configured per group so traffic only reaches healthy targets. (Lessons 8, 9)
Target type ipThe required target type for services using awsvpc, because the task is associated with a network interface rather than an EC2 instance. Instance targets are the wrong unit. (Lesson 8)
Health checkA periodic probe. A target group health check decides whether the load balancer sends traffic; the ECS service scheduler treats a failure as a reason to replace the task. Two loops, different jobs. (Lesson 9)

Named, not taught

These come up next to the course material and are deliberately outside its scope. They are listed so the boundary is visible rather than invisible.

TermOne line
Service ConnectECS service-to-service communication with automatic discovery using short names and standard ports, without a load balancer.
Service discoveryThe Route 53 based alternative: a namespace makes a service discoverable through DNS.
Amazon VPC LatticeA managed application networking service connecting and securing services across accounts and VPCs.
Task role and task execution roleTwo distinct IAM roles: the task role is what the application uses, the execution role is what the ECS agent uses to pull images and write logs.
Amazon ECRThe AWS container registry. Relevant here only as the thing a task must reach to pull its image.
Blue/green deploymentShifting traffic to a parallel new version rather than replacing tasks in place.
VPC peering and Transit GatewayTwo ways to route privately between VPCs: a direct pairing, and a Regional hub that interconnects many networks.
VPC Flow LogsRecords of IP traffic going to and from network interfaces in a VPC, including task interfaces.
