Route tables and what public means

There is no setting named "public" on a subnet. A subnet is public because of one line in a table: send everything not local to an internet gateway. Once that lands, the whole public and private vocabulary stops being jargon and starts being a routing decision you can read off a diagram.

The concept

A route table "serves as the traffic controller for your virtual private cloud", holding "a set of rules, called routes, that determine where network traffic from your subnet or gateway is directed."1 Each route is a pair: a destination, meaning "the range of IP addresses where you want traffic to go", and a target, meaning "the gateway, network interface, or connection through which to send the destination traffic."2

That pairing is the entire mechanism. A packet leaves a resource, its destination address is compared against the routes in that subnet's table, and the matching route says which exit to hand it to. No matching route means the packet goes nowhere.

Two routes decide almost everything. The second one is where public and private are settled.

Step 1 — Every subnet has exactly one route table

You can associate a subnet with a table you created. If you do not, it falls back: the main route table "automatically comes with your VPC" and "controls the routing for all subnets that are not explicitly associated with any other route table."2 So there is no such thing as a subnet without routing. There is only a subnet whose routing you have not looked at.

One table can serve many subnets, which is how a matched set of private subnets across three zones stays consistent: same table, same rules, three places.

Step 2 — The local route is always there

Every route table contains a local route, "a default route for communication within the VPC."2 Its destination is the VPC's own address range, and its target is the VPC itself. This is why any resource in a VPC can route to any other resource in the same VPC without configuration, across subnets and across zones.

Routing is not permission. The local route means a path exists; whether the traffic is allowed to arrive is decided by a separate layer, which is Lesson 5. Keeping those two apart is most of what makes AWS connectivity debugging tractable.

Step 3 — A public subnet is one with a route to an internet gateway

Add a route with destination 0.0.0.0/0 and an internet gateway as the target, and every packet with no more specific match heads for the internet. A subnet whose table has that route is what everyone means by a public subnet. A subnet whose table does not have it is a private subnet. The words describe the routing, not a property AWS stores.

The docs describe the default VPC in exactly these terms: it has "an attached internet gateway, a route in the main route table that sends all traffic to the internet gateway", and therefore "an EC2 instance that is launched in a default subnet automatically has access to the internet."3 The internet access is a consequence of the route, spelled out as such.

Step 4 — A public IP address is the other half, and it is a separate decision

The route gets a packet to the edge. Getting an answer back requires the resource to have an address the internet can reply to. The docs are precise about the default case: "By default, each instance that you launch into a nondefault subnet has a private IPv4 address, but no public IPv4 address, unless you specifically assign one at launch, or you modify the subnet's public IP address attribute. These instances can communicate with each other, but can't access the internet."3

Two independent things, then. The subnet's route table decides whether a path to the internet exists. The resource's address decides whether it can use that path. Missing either one produces the same symptom, which is why "it can't reach the internet" is never a one-check diagnosis.

Why it matters

This is the lesson that turns AWS diagrams into something readable. Every box labelled "public subnet" is making a claim about a route table, and you can ask to see it. Every "why can't this reach out" question splits immediately into two: is there a route, and does this thing have a usable address.

It also sets up the rest of the network. Gateways are not special powers; they are targets that a route can point at. Once the route table is the thing doing the deciding, adding an internet gateway, a NAT gateway, or an endpoint is the same move each time: give traffic a destination and point it somewhere.

Key line A subnet is public because its route table sends 0.0.0.0/0 to an internet gateway. There is no public flag. And the route alone is not enough: the resource also needs an address the internet can answer.
The common trap The near-miss is "a public subnet is one where resources get public IP addresses." Auto-assigning a public address is a real subnet setting, and it is the wrong half of the answer. Without the internet gateway route, the packet never reaches the edge and the public address does nothing. The strong answer names both halves and says which one the term "public subnet" refers to.

Recall — answer out loud before peeking:

① What makes a subnet public?

show answer

Its associated route table contains a route whose destination is 0.0.0.0/0 and whose target is an internet gateway. Nothing else marks it as public.

② A subnet was created and no route table was associated with it. What is its routing?

show answer

It uses the VPC's main route table, which controls routing for every subnet not explicitly associated with another table. It always has the local route, so it can reach the rest of the VPC.

③ An instance sits in a subnet with an internet gateway route and still cannot reach the internet. Name one reason that is consistent with everything in this lesson.

show answer

It has only a private IPv4 address, so there is no address for return traffic. The path exists and the resource cannot use it.
